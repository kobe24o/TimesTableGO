# 乘法口诀背诵跨平台改造设计

## 目标与范围

将现有 Android Kotlin MVP 重构为 Flutter 应用，在 Android 与 iOS 提供一致的中文乘法口诀背诵体验。核心目标是让孩子能自然地朗读口诀，看到正在识别的文字，并得到清楚、温和的“正确 / 漏读 / 读错”反馈。

首发定位为由家长协助使用的学习工具。应用不使用儿童导向的广告文案；广告只预留受控入口，默认关闭，待 AdMob 账户和政策配置完成后才启用。

本期不做账户体系、云端同步、排行榜、社交分享、付费墙或多广告平台聚合。

## 产品体验

### 主页

主页是“今日背诵”而不是复杂仪表盘。页面显示今日练习建议、连续练习天数、薄弱口诀提示，以及一个醒目的“开始背诵”按钮。底部仅保留“练习、进度、家长”三个入口。

### 背诵流程

1. 用户选择范围：整张九九表、指定几的口诀或薄弱复习。
2. 应用显示一张大字号口诀卡，例如“七八五十六”，并提供按住说话按钮；可在家长设置中选择自动录音。
3. 调用系统语音识别并逐步展示转写内容；若设备不支持或识别失败，展示可重新录制的状态，不把未识别误判为答错。
4. 将目标口诀、识别文本和仅必要的上下文发送到用户配置的唯一大模型。
5. 大模型必须返回严格 JSON：`correct`、`status`（correct / missing / wrong / reordered / unclear）、`heard`、`feedback`。应用本地校验 JSON、限制展示长度；网络失败时退回本地标准化文本比对，并标记“本地判定”。
6. 显示绿色通过状态或可视化纠错卡；错误时高亮目标口诀中需要重读的位置，提供“再背一次”。通过后更新进度并进入下一题。

### AI 老师

单一大模型同时承担两件事：对 ASR 文本作背诵判定，以及依据本地练习统计生成老师鼓励。老师寄语只在完成一组练习、达成连续正确或家长在进度页主动请求时生成，避免每题额外请求和成本。

### 家长设置

设置页需要家长门槛后才可进入。只保留：大模型 API Base、模型名、API Key、是否朗读题目、录音方式、练习时长、隐私与广告开关。API Key 存放在设备安全存储区，绝不写入源码、日志、导出文件或分析事件。

## 技术架构

### Flutter 客户端

- 使用 Flutter 稳定版；业务代码放入 `lib/`，按 feature 分为 `practice`、`progress`、`parent_settings` 与 `ads`。
- 语音识别抽象为 `SpeechRecognitionService`。Android 通过系统 `SpeechRecognizer`，iOS 通过 `SFSpeechRecognizer`；平台权限与不可用状态由同一接口暴露。
- `RecitationJudge` 负责创建单一 LLM 请求、解析固定 JSON、以及在失败时运行本地标准化比较。LLM 调用使用用户自行配置的 OpenAI-compatible API。
- `PracticeRepository` 本地持久化尝试记录、掌握度和设置。先使用加密/安全存储保存密钥、普通本地数据库保存练习历史。
- UI 使用 Material 3，并针对 iOS 的安全区、字体缩放和语义标签做适配。

### LLM 判定契约

输入只含目标口诀、ASR 文本和语言（`zh-CN`）。系统提示要求模型不要评价孩子人格、不要虚构转写，并输出例如：

```json
{"correct":false,"status":"missing","heard":"七八五","feedback":"已经很接近了，再补上“十六”就完整啦。"}
```

应用接受未知字段但只依赖该四个字段；无效 JSON、超时、HTTP 错误与空识别结果均有可恢复 UI。

### 广告预留

`AdService` 为可替换接口。首发实现 `DisabledAdService`，所有广告位默认为不展示。以后接入 AdMob 时，仅在家长模式下、完成一组练习后的独立奖励页展示激励视频；不得在录音、判题、错误订正或儿童年龄未知状态插入广告。正式 App ID、广告单元 ID 通过构建配置提供，仓库只保留测试 ID / 示例变量。

## 数据与隐私

- 音频只交给系统识别器，不在应用内保存、不上传至自建服务。
- 发送给 LLM 的数据最小化为目标口诀和转写文本；不发送孩子姓名、设备标识符、完整历史或原始录音。
- 首页可在无网络状态下使用本地比较练习；需要 AI 时明确说明“使用你配置的模型服务”。
- 发布前必须提供隐私政策，并分别在 Google Play Data safety 和 App Store Privacy Nutrition Label 中据真实 SDK/数据流填写。

## 验收标准

1. 同一 Flutter 工程能构建 Android APK/AAB 与 iOS IPA（由有 Apple 签名权限的环境完成）。
2. 用户无需配置 ASR、TTS、百度或 Azure 账户；仅在家长设置中可配置一组 LLM 参数。
3. 一次背诵能够展示部分转写、给出正确 / 漏读 / 读错 / 顺序错 / 不清楚结果，并允许重录。
4. LLM 失败不会让练习卡死，并明确标识本地判定。
5. 练习与进度在离线重启后保留；API Key 不出现在普通偏好设置或调试输出。
6. 广告代码默认关闭、无正式广告 ID，开启前不影响核心练习流程。
7. 所有新增核心规则具备单元测试，关键练习流程有 widget/integration 测试。
